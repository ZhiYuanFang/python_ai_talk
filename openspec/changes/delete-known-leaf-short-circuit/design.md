## Context

删除在操作轨用「删除|删掉|去掉|取消记录」即可定轨。事件阶梯是词典、别名、说法飞轮、Go 备注反查、事件小模型，之后父事件或未识别才用附近历史猜叶子。词典命中时不会进入反查。

事件一旦有了 `event_id`，`resolve_segment` 仍把删除和记一笔放在同一道门后：备注明细（含画像昵称）、数量、时间都跑。落库时只要本批含修改或删除，就调用 `resolve_locate`；本地定位词未命中时会查飞轮再问模型，默认策略其实就是最近一条。

## Goals / Non-Goals

**Goals:**

- 删除且事件已是唯一叶子时，停掉备注明细、数量、时间。
- 事件名未定时，保留 Go 备注反查和后续事件阶梯。
- 父事件删除仍猜叶子；猜成叶子后再停旁路。
- 纯删除且句中没有定位词时，直接按最近一条选行，不问定位模型。

**Non-Goals:**

- 不改记一笔、修改的备注、数量、时间。
- 不改修改的定位解析。
- 不扩大删除动词表，不改事件词典匹配。
- 不把「昨天」这类时间用来挑选要删的那一行。

## Decisions

1. **唯一叶子才短路。** `target_type` 为删除，且事件存在、不是父事件、没有消歧列表。词典、别名、反查唯一命中、历史猜叶子成功都算。父事件在猜叶子之前不算已确定。
2. **短路内容。** 不读宝宝画像，不查备注飞轮，不调备注模型，不记备注缺口。数量保持空，不记缺量。不解析钟点或日词窗口。反查或别名带回来的关键字不写入删除事件的 `remark`。
3. **未定事件仍走阶梯。** 词典、别名、说法飞轮都空时，继续 Go 备注反查。多条消歧、零命中后的事件模型、历史猜叶子保持现状。消歧早退本来就不进备注明细。
4. **定位只收紧纯删除。** 本批待落库项全部是删除，且 `match_local_locate` 为空：策略 `latest`，不查定位飞轮、不调定位模型、不记定位缺口。本地命中「正在进行」「已完成」「最近一条」等既有词时，用该结果。本批含修改时，仍走现有 `resolve_locate`。
5. **拼音视图不重排。** 段首仍切一次拼音。删除短路发生在事件解析之后，不改各维视图互不写回的约定。

## Risks / Trade-offs

- [「删掉昨天的配方奶」不再用「昨天」收窄记录] → 接受。事件已定后按定位策略选行；无定位词就是该事件最近一条。
- [反查关键字不再留在删除事件的备注字段] → 该字段不参与选行，确认话术只用事件名。
- [同一句里又有修改又有删除] → 定位仍走现有路径，避免改到修改的选行。
