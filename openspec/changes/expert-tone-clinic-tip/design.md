## Context

`clinic_answer.py` / `tip_answer.py` 当前人设为「有经验闺蜜」，并强制：有对话必点名、有记录必点名、对话感引导收尾、同月龄代入；clinic 无史路径还强制「征求肯定」。用户要求改为育儿专家、提示词变短、避免决断医疗、记录有则必点、对话非必点、**不需要引导征求肯定**。

基线 capability `bestie-companion-persona`、`grounded-bestie-prompts`、`bestie-dialogue-hooks` 与上述行为绑定，本变更同步改规格。

## Goals / Non-Goals

**Goals:**

- clinic + tip 共用原则：育儿专家、温和清晰、非医生、不诊断不开药。
- 注入喂养记录 → 正文必须点 1 条相关事实；点查/汇总仍以记录为准。
- 注入 chat_context → 可参考，不强制点名；禁止编造「上次你说」。
- 删除征求肯定硬约束；删除强制闺蜜抛话头与同月龄代入硬要求。
- 明显缩短 system / closing 文案。

**Non-Goals:**

- 不改路由、图拓扑、needs_history 判定逻辑。
- 不删除 chat_context 注入能力（仍可放入 user 消息作背景）。
- 不改 implicit feedback 代码路径（只是提示词不再诱导肯定）。
- 不强制抽 shared prompt 模块（可复制精简文案，保持 clinic/tip 文件分离）。

## Decisions

### D1: 人设 = 育儿专家（非闺蜜、非医生）

口吻：专业、温和、克制；用「你/宝宝」。禁止自称医生/儿科助手；禁止闺蜜式「接情绪→抛话头」剧本作为主结构。

### D2: 有据不对称

| 依据 | 规则 |
|------|------|
| 喂养记录块非空 | MUST 点名 1 条相关事实 |
| chat_context 非空 | MAY 参考；MUST NOT 要求必须点名 |
| 皆空 | 禁止编造记录/上次对话 |

### D3: 去掉征求肯定与强制对话钩子

- 删除 clinic 无史「收尾必须问是否说得对/有用」。
- 删除 tip/clinic「尽可能以引导式话题收尾」作为硬约束（可不写或写「可选」）。
- 删除「同月龄代入」硬允许/硬推（月龄仍可注入宝宝信息，但不要求「我家要是…」）。

### D4: 精简结构示意

Clinic system（有史）目标体量：角色 + 记录必点 + 对话可参考 + 点查/汇总要点 + 安全边界。  
Clinic 无史：角色 + 禁止编本机记忆 + 安全边界（无征求肯定）。  
Tip：角色 + 针对事件开场 + 记录必点 + 对话可参考 + 短 + 安全。

Closing 只保留与本轮数据相关的短约束（有史则点记录；无史则禁编；附上家长问题/事件名）。

### D5: Intent 共用

`call_clinic_agent` 继续走 `clinic_answer` 构建函数；改文案即自动覆盖 intent 内嵌路径。规格把「闺蜜模板」改为「育儿专家模板」。

## Risks / Trade-offs

- [续聊率下降] → 接受产品取舍；对话块仍注入供模型可选承接。
- [隐式采纳信号变少] → 不靠征求肯定；依赖既有多轮判定，不在本变更重做飞轮。
- [专家腔变说明书] → 文案明确「勿清单标题、勿恐吓」；tip 保持短开场。

## Migration Plan

1. 改提示词与 closing；部署后行为立即切换。
2. 回滚：恢复旧镜像/旧提示词文件。

## Open Questions

- 无（征求肯定已明确不要；引导抛话头按非强制处理）。
