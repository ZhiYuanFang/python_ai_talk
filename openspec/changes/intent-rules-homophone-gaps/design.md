## Context

段解析顺序是 OP → EVENT → REMARK → QTY → TIME。数量、钟点、日词、删/改/结束、事件正式名和 `extra_names` 已有本地规则。查记录还是预测、预测格子、记一笔、定位等仍先飞轮再小模型。规则缺口 JSONL 能记任意 `dimension`，但 `GET /admin/rule-gaps` 不带维度时只返回 `time` 与 `quantity`。查史语境类缺口已在写，默认列表看不见。

## Goals / Non-Goals

**Goals:**

- 同音替换只发生一次，在各维规则之前，词表来自当前事件字典。
- 各维本地规则命中则短路。
- 规则未命中就记缺口，飞轮命中与小模型都记，并用 `reason` 分开。
- 先发布 Python 列表契约，再改 Go Hub 展示。

**Non-Goals:**

- 不改思考字幕过滤，不恢复设备闸门。
- 不把形状维单独记缺口。
- 不同音替换对外回执和十分钟对话里的原话。
- 不在规则含糊时硬判（「多少」单独出现不得同时决定查记录和预测用量）。

## Decisions

### D1：同音只替换唯一事件词

用事件 `event_name` 与 `extra_names` 建拼音索引，字典刷新时重建。句中连续片段的拼音（带调）只落到一个事件词时，把该片段换成这个词。两个事件同音，或对不上，保持原文。解析、飞轮键用替换后的段文本；`utterance` 字段与对外句子用 ASR 原文。

### D2：规则在飞轮之前

每一维：本地规则 → 未中则记缺口并继续飞轮 → 飞轮未中再小模型并再记（或同一条缺口更新为走了模型，实现可记一条，`reason` 取最终去向）。已有的数量、钟点、日词、删改结束、事件名匹配保持在飞轮之前。补上的规则至少包括：记一笔、查记录/预测、预测的何时/用量/用时、定位策略里已有稳定说法。规则用整句框架，例如「吃了多少」是查记录，「这次要吃多少」是预测用量。

### D3：缺口维度

`op`、`read_source`、`predict`、`event`、`remark`、`quantity`、`time`、`locate`，以及已有的 `history_speak_context`、`history_missing_event`。段原文用同音替换后的文本，`utterance` 用 ASR 原文。短窗去重仍按维度加段原文。

### D4：列表先放开，Hub 后改

未指定 `dimension` 时返回全部 open 记录，按时间新到旧分页，条目含 `dimension`。指定维度时行为不变。Go Hub 在该契约之后改：一张列表加维度筛选，不再只渲染时间与数量两块。本仓任务完成前不依赖 Go 已发布。

## Risks / Trade-offs

- [同音误替换] → 仅唯一命中才替换；带调拼音。
- [规则过宽把查记录和预测打反] → 不中则落到飞轮，并记缺口。
- [缺口变多] → 120 秒去重仍在；Hub 用维度筛选。
- [Go 页尚未改时多出维度] → Python 先返回全量，旧页面若写死两列会暂时挤在一起，所以 Go 紧跟 Python。

## Migration Plan

先发 Python。已有 `time`/`quantity` 行仍可读。再发 Go Hub。回滚是恢复列表默认过滤，并去掉同音与新增规则短路。
