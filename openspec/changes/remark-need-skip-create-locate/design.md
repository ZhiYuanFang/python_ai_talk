## Context

记一笔「吃了120配方奶」在段解析里已经定轨、定事件、定数量。备注分支只在别名已经带备注时跳过模型，否则整句查飞轮，不中就问备注模型。模型按约束返回空字符串，空备注仍会写入飞轮并记规则缺口。

落库在 `execute_history_crud` 里无条件调用 `resolve_locate`。填旧记录编号的函数只处理修改和删除，记一笔的开始时间由钟点规则写入新记录。纯记一笔问定位，返回值用不上。

## Goals / Non-Goals

**Goals:**

- 没有剩余明细时备注为空，并且不查飞轮、不问备注模型。
- 本批没有修改和删除时不调用改删定位。
- 「早上8点吃了120配方奶」仍按早上 8 点新建，不按最近一条改旧记录。

**Non-Goals:**

- 不改数量、钟点、事件名的既有本地规则。
- 不改别名已经带备注时的跳过方式。
- 有修改或删除的批次仍走定位。

## Decisions

### D1：先剥再判断有没有备注

在备注飞轮之前，从段原文去掉已定事件名、已解析数量，以及「吃了 / 喝了 / 拉了 / 尿了 / 睡了」。去掉后只剩空白或语气词，则 `remark` 为空并结束本维。不查备注飞轮，不调用备注模型，不把空备注写回飞轮，不记这条为规则缺口。

去掉后仍有描述，例如「有点凉」，继续现有飞轮再到模型。

### D2：按本批操作决定是否定位

`collect_event_items` 之后，仅当存在 `update` 或 `delete` 时调用 `resolve_locate`。全是记一笔或结束时不调用，策略保持默认，填编号函数会跳过这些项。同一批混合时仍调用一次定位，只用于修改和删除。

记一笔的 `start_time` 继续走段解析里的钟点覆盖，与定位无关。

## Risks / Trade-offs

- [套话名单漏掉口语] → 剥不干净就留给飞轮和模型，不把有描述的句子判成空备注。
- [事件名是描述的一部分] → 只去掉已定事件名本身，不去掉其余字。

## Migration Plan

只改本仓 Python。回滚是恢复备注始终可进飞轮，以及落库始终调用定位。
