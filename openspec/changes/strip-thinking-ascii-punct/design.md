## Context

`ThinkingSentenceCrRewriter.feed` 先调用 `_strip_display_ascii`，再按句界拆分并在下一句段首加 `\r`。现有剔除表是拉丁字母与 `{}[]"'`:#*_`。`,` `.` `(` `)` `>` `-` 等 ASCII 标点不在表内。字母去掉后，纯英文思考会剩下一串符号并被推到客户端。

编排字幕 `emit_thinking` 与回答正文不经过本模块。

## Goals / Non-Goals

**Goals:**

- 思考字幕再去掉英文标点，点名字符为 `,` `.` `(` `)` `>`，并覆盖同类 ASCII 标点。
- 整段被剔成空白时不推送。
- 中文、数字、空白、`\r`、中文句界与中文标点保持原样。

**Non-Goals:**

- 不改口播回答、意图终答 JSON、固定编排字幕。
- 不删中文标点（`，。！？、；：` 及全角括号）。
- 不把英文标点换成空格或中文标点。
- 不要求剔除后的字幕仍然通顺。

## Decisions

1. **只扩同一张剔除表。** 在 `_STRIP_CHARS` 增加：`, . ( ) > < - ; / \ | = + ~ @ % ^ & ! ?`。`->` 被拆成 `-` 与 `>`，跨 token 也能去掉。直接删除，不留占位。

2. **英文 `.!?` 退出句界。** 剔除发生在分句之前，这三个字符到不了句界判断。`_SENTENCE_END` 只保留 `。！？`，避免注释和代码仍把已删除的英文句点当成句界。中文句号仍触发下一句段首 `\r`。

3. **空增量沿用现有丢弃。** 剔除后只剩空白或 `\r` 时，现有 `feed` 返回空列表，不改句界等待状态。不另做「无汉字则丢弃」：中文标点仍可能单独出现，按用户范围保留。

4. **数字中的小数点一并删除。** `1.5` 会变成 `15`。思考字幕是闪过的短句，接受这个结果，不按数字上下文保留 `.`。

## Risks / Trade-offs

- [英文思考不再按 `.!?` 切句] → 中文 `。！？` 仍切句；纯英文增量在字母和符号都去掉后通常整段为空，不会闪标点。
- [小数点消失] → 接受；字幕不承担精确数值展示。
- [中文逗号、顿号仍会留下] → 用户范围是英文符号；中文标点是正常字幕的一部分。

## Migration Plan

- 只改 `thinking_sentence_cr.py` 的字符表、句界集合和中文注释。
- 回滚即恢复原剔除表与含 `.!?` 的句界集合。
