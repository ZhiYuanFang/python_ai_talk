## Context

生日接口返回 `babyName`、`birthday`（Unix 秒，`0` 表示未设置）、`sex`（`0` 女，`1` 男）。诊疗提示词读 `gender`，该键不存在，性别一直是「未知」。月龄已经用 `birthday` 按上海日历计算。覆盖缺口软回复按一份错误的字段名单摘取，日志里只剩下 `sex=0`。留意模块已把 `sex` 写成女或男，但诊疗和软回复没有共用这套说法。

## Goals / Non-Goals

**Goals:**

- 诊疗与软回复都用同一套中文画像：有名字写名字，性别由 `sex` 译成女或男，月龄由 `birthday` 写成「N 个月」。
- 缺项写未知或省略，不把原始数字交给模型。

**Non-Goals:**

- 不改生日接口，不重算预测算法。软回复仍只附已有预测快照。
- 不改留意模块已有的性别行。
- 不把画像整包 JSON 塞进提示词。

## Decisions

1. **性别只认 `sex`。** `0` 为女，`1` 为男，其它（含缺省）为未知。不再读 `gender`。
2. **月龄继续走现有生日解析。** Unix 秒与 `0` 的语义已在共享月龄函数里，诊疗和软回复都调用它，不另写一套。无法解析则月龄为未知。
3. **名字用 `babyName`，空串不写。** 诊疗在现有「月龄 / 性别」两行上，有名字时多一行。软回复用同样三行，替换现在的 `键=值` 摘取。
4. **文案放在共享小函数里，由 clinic 与 feeding 软回复调用。** 避免两处各写一份性别对照。函数只产提示词句子，不改画像字典本身。

## Risks / Trade-offs

- [历史数据里 sex 不是 0 或 1] → 写成未知，不猜。
- [birthday 为 0] → 月龄未知，模型不得假设月龄（诊疗原约束保留）。

## Migration Plan

无数据迁移。上线后问年龄的失败软回复和诊疗回答会看到女或男以及月龄。回退即恢复读 `gender` 与键值摘取。

## Open Questions

无。字段名与 `0` 女 `1` 男已按 Go 保存请求的说明定死。
