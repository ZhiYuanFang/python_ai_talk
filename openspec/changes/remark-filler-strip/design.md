## Context

`segment_has_remark_detail` 会剥事件片段、钟点、数量、时段词、记一笔套话和单字语气词。两个字的「还是」剥不掉。「还是拉屎了。」在删掉事件名「拉屎」之后剩下「还是」，于是进入备注飞轮和备注模型。

宝宝画像已有 `get_baby_profile(device_no)`，名字字段是 `babyName`。意图图在 `resolve_segments` 时还没有先拉画像。

## Goals / Non-Goals

**Goals:**

- 备注明细判断前剥掉固定废话和「孩子」「宝宝」。
- 同一段用设备画像里的 `babyName` 再剥一次，含一个字的昵称。
- 剥完为空则跳过备注飞轮、模型和缺口。

**Non-Goals:**

- 不把昵称写进规则名词文件。
- 不把这些词加进操作轨记一笔动词。「拉屎了」仍不是「拉了」。
- 不改飞轮、对外复述所用的原文。
- 不把「有点」「偏」「黄」这类可能是明细的词放进废话表。

## Decisions

### D1：固定词进备注词表

在 `dim_rule_lexicon.py` 增加备注废话元组：还是、就是、然后、那个、这个、其实、反正、孩子、宝宝。并入 `REMARK_VIEW_WORDS`，使近音转换和正则剥离用同一份。`segment_has_remark_detail` 在现有套话剥离时再删这组词。

### D2：昵称当次传入

`resolve_segment` 在备注判断前调用 `get_baby_profile`。取出的 `babyName` 作为参数传给明细判断，做字面删除。不进入拼音索引，因此一个字也会被删掉。请求失败或字段为空时，参数为空字符串，固定词照常剥离。

### D3：只决定要不要进备注

剥完仍有文字时，后续仍是备注飞轮再模型。本变更不代替模型抽取「有点凉」。

## Risks / Trade-offs

- [「菠菜还是南瓜」被删掉「还是」] → 剩下「菠菜南瓜」，仍有明细，仍进模型。
- [画像多一次请求] → 只在将要做备注判断时拉取；失败不阻断记一笔。
- [昵称碰巧是明细里的一个字] → 按产品要求删除该昵称。一个字的名字只做字面删除。

## Migration Plan

只发 Python。回滚时去掉废话剥离和画像读取，备注判断回到现有套话表。无数据迁移。
