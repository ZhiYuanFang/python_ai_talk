## Context

紧凑历史把同一年的日期写成 `10-15`，跨年写成 `2025-10-15`。日汇总兜底把这段文字交给模型，提示词没有规定日期说法，模型就照抄。只在提示词里要求「写成几月几号」仍容易被原文带回去。

现有对外提示词多写「家长」，但没有禁止「宝妈」。基线旧文案还有「对妈妈说话的闺蜜」。产品口吻已是育儿专家，说话对象应明确为孩子的家长。

## Goals / Non-Goals

**Goals:**

- 家长听到的日期是「10月15日」；跨年带年份。
- 对外回答不把对方叫成宝妈、宝爸或妈妈。

**Non-Goals:**

- 不改钟点 `08:30` 的写法。
- 不改内部解析提示词（分句、事件、时间、数量）的角色句。
- 不恢复闺蜜人设，不改育儿专家定位。

## Decisions

1. **改共享日标签，而不是只改一句提示词。** 同一年 `M月D日`，跨年 `YYYY年M月D日`。查史对比、诊疗、留意和预测注入都走这套标签，避免一处口语、一处 `10-15`。
2. **兜底提示词再写一句。** 日汇总兜底和预测兜底要求日期用「几月几号」，禁止连字符日期。模型若自行概括，也不要退回 `10-15`。
3. **对外系统提示词加一句说话对象。** 诊疗（有史/无史）、查史兜底、无事件短猜、预测兜底、失败后直接回答：说话的人是孩子的家长，用「你」称呼，不要称宝妈、宝爸或妈妈。成长轨迹与留意若正文是给家长看的，同样加这一句。

## Risks / Trade-offs

- [留意或诊疗的对照文本从 `10-15` 变成「10月15日」] → 这是同一套标签，家长和模型看到的日期一致。
- [模型仍口头说宝妈] → 提示词写明禁止；不在代码里做事后替换。

## Migration Plan

无数据迁移。上线后新的汇总和回答即用新日期和新称呼。回退即恢复 `MM-DD` 标签并去掉称呼句。

## Open Questions

无。日期写法与「孩子的家长」已按讨论定死。
