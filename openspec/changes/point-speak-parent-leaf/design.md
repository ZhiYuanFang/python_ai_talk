## Context

点查在段解析里已能由「上次 / 上一次」定成查记录、点查，时间窗也会跳过。播报策略 `point_pick` / `open_speak` 仍在 `resolve_history_speak_policy` 里整句飞轮，不中再问「查史点查播报策略」模型。提示词第 5 条已经写死常见说法，模型只是复述。

父事件命中后，`guess_leaf_from_history` 把子孙叶子和最近历史交给模型选一个叶子。点查要的是「这些子事件里，谁的最近一条开始得最晚」。

## Goals / Non-Goals

**Goals:**

- 点查播报的常见说法在飞轮之前由本地规则定两个标签。
- 父事件且为点查时，用各子孙叶子最近一条的开始时间选定叶子，不调用猜叶子模型。
- 这些叶子都没有历史时，短问子事件名并等待确认。

**Non-Goals:**

- 不改预测口播、日汇总口播、没命中时的软回复。
- 事件未识别、多候选消歧仍走原有猜测。
- 父事件的记一笔、修改、删除不改成按时间选叶子。
- 不为播报策略新开规则缺口维度。

## Decisions

### D1：播报规则先于飞轮

在 `resolve_history_speak_policy` 查飞轮之前匹配整句：

- 含「上次」「上一次」或「最近一次」→ `prefer_completed` + `in_progress`
- 否则含「多久了」或「多长时间了」→ `latest` + `elapsed`

「上次」先判，这样「上次睡眠多久」不会被「多久」收成最近一条。命中直接返回，不查飞轮、不调模型、不回写飞轮。不中则保持现有飞轮再到模型。

### D2：父事件点查用开始时间选叶子

仅当本段已是查记录点查、且事件是父节点时替换猜叶子模型。用现有子孙叶子收集，一次按这些叶子编号拉最近记录。每个叶子只留开始时间最大的一条，再在这些条里取开始时间最大的叶子。开始时间相同则取子孙列表中更靠前的叶子。

选中的叶子仍标记为历史选定，避免把「上一次喂养是什么时候」整句写进该叶子的说法飞轮。

进行中只要开始更晚，就先定这个子事件。定叶子之后，播报再按 D1 决定怎么说这一叶子的记录。

### D3：没有记录就短问事件名

一次拉取结果里这些叶子都没有行时，不播报、不调模型。走现有多叶子确认，问句只列叶子名，例如「是配方奶、母乳，还是辅食？」。字典下没有子孙叶子时保持原有未识别结果，不编造事件名。

## Risks / Trade-offs

- [进行中比已完成更晚] → 先定进行中那个子事件；「上一次」的播报规则再在该叶子里优先已完成。这是两步，不在选叶子时改用已完成优先。
- [拉取条数上限漏掉更早的叶子] → 胜出者一定在按时间最近的那批里；没有任一条才追问。
- [问句叶子很多] → 仍只列名称，不加解释。

## Migration Plan

只改本仓 Python。回滚是恢复播报先查飞轮，以及父事件点查继续调猜叶子模型。
