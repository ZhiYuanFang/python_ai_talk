## Context

更新轨有两处把「结束」收成新建。

整句飞轮命中更新后，句子里有「睡醒 / 醒了 / 结束 / 停了 / 好了」就把子操作写成 `end`。这时事件还没对齐，分不清是不是计时。

落库收集时，非计时且子操作是 `end`，会改成 `create`。另外，没有进行中记录时，`_rewrite_end_without_open` 对所有 `end` 都转成新建，不限计时。

计时事件仍需要这条判断：有进行中就结束，没有就补记。非计时事件在轨已是更新时，应只修改已有记录。

## Goals / Non-Goals

**Goals:**

- 非计时、轨已是更新：子操作保持 `update`，不因结束词或有没有结束时间改成新建。
- 计时事件维持：有进行中则 `end`；没有进行中则转补记新建。

**Non-Goals:**

- 不改创建轨。「睡着了」仍是开始计时或补记，不是修改。
- 不改删除、查记录。
- 不放宽结束词表本身。词表仍可把计时句收成 `end`。

## Decisions

### D1. 事件类型已知后再收 `end`

飞轮或小模型可以先把更新句标成 `end`。事件对齐之后，仅当字典类型是计时（`event_type=time`）才保留 `end`。非计时且当前轨是更新时，子操作改回 `update`。

不在飞轮命中处用词表直接决定最终操作，因为那时还没有事件类型。

### D2. 落库不再把非计时 `end` 收成新建

`collect_event_items` 里「非计时且 `end` → `create`」改为「非计时且 `end` → `update`」。这是兜底，避免上游漏改时仍然新建一条。

### D3. 无进行中转补记只扫计时

`_rewrite_end_without_open` 只处理计时叶子。非计时的 `end` 或 `update` 不查进行中、不改成 `create`。计时且没有进行中时，仍按现有补记（闭合则 `one`，否则追问起止）。

## Risks / Trade-offs

- [非计时句里的「好了」不再结束一条进行中记录] → 非计时本来没有开表；结束开表只留给计时。
- [上游仍写出非计时 `end`] → 落库兜底改成 `update`，不新建。
- [计时无进行中仍会新建] → 这是补记，保持不动。

## Migration Plan

无数据迁移。回滚时恢复「非计时 `end` → 新建」与全类型的无进行中改写。
