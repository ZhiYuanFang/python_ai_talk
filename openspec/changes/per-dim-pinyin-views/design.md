## Context

段解析入口现在调用 `apply_event_homophone`，把唯一带调同音片段写进 `draft.text`。操作轨、事件、备注、飞轮都读这句改写稿。词表只在事件字典刷新时重建，且只收完全同音。操作轨、播报、定位、备注的名词写在各自正则里，没有拼音缓存。

`pypinyin` 的 `errors="ignore"` 会丢掉数字。带「120」的句子字数和音节数对不上，现有函数整句不替换。

未收版变更 `intent-rules-homophone-gaps` 要求各维共用替换后的事件词。本变更改成各维视图隔离。基线 `v0.0.1` 没有这条需求。

## Goals / Non-Goals

**Goals:**

- 一段原文只切一次按字对齐的拼音，各维共用这份只读音节。
- 词表拼音全局缓存：规则名词在导入时，事件名在字典载入和手动刷新时。
- 完全同音，或整段恰好一个声母不同（韵母、声调、音节数相同），或整段恰好一个声调不同（声母、韵母、音节数相同），且全表只有一个词时，才替换。
- 每一维从原文生成自己的视图，本地规则只读本维视图。
- 非事件规则名词单模块维护，正则由名词元组拼出。

**Non-Goals:**

- 不在同一个音节上同时改声母和声调。「是了」对「吃了」仍保持原文。
- 不把事件正式名或 `extra_names` 写入规则名词模块。
- 不把数字、单位结构、钟点格式放进名词表。
- 不改飞轮、小模型、对外复述、十分钟对话所用的原文。
- 不新增听写混淆对。

## Decisions

### D1：一段一刀，按字留空位

在 `resolve_segment` 入口对原文逐字取带调拼音。汉字得到一个音节；数字、字母、标点得到空位。空位不参与词表比对，也不把整句判为无法对齐。各维读取同一份音节，不再各自调用拼音。

备选是每维对改写稿重新转拼音。那样后一维会看到前一维的正字，和「从原文处理」相反。

### D2：替换条件

音节数至少为 2。从左到右取最长片段。先查完全同音且该拼音只对应一个词。否则收集两类候选：韵母和声调相同、声母只差一个音节的词；声母和韵母相同、声调只差一个音节的词。合并后只剩一个词才替换。已是正字的片段占住跨度，避免被更短的词拆开。

同一维的全部名词放进同一次最长匹配，避免「吃了」截断「吃了多少」。

### D3：视图互不写回

转换函数接收原文、只读拼音和该维缓存，返回本维视图。不修改原文，不把视图交给其它维。事件维用事件缓存；操作轨、播报、定位、备注各用规则名词模块里的对应元组。

`draft.text` 保持语音识别原文，供飞轮和小模型使用。

### D4：缓存时机

规则名词缓存随模块导入构建，存带调音节以及声母、韵母、声调，并建好完全同音索引、声母分桶和声调分桶。事件缓存仍挂在 `event_cache` 字典写入和手动刷新两处，与字典锁一起替换。请求路径只读缓存。每次生成视图写一条 INFO：维度、result、原文片段、视图片段。未安装 `pypinyin` 时缓存为空，视图等于原文，`result` 为 `no_pinyin`。

### D5：名词单源

新增 `app/feeding/services/dim_rule_lexicon.py`，列出操作轨、播报、定位、备注所用的名词元组。两维共用的说法（如「上次」）在文件里只写一份，由两维一起引用。`dim_local_rules`、`history_speak_policy`、`segment_remark` 的正则改为由这些元组拼接。本地规则的判断顺序保持现状。

### D6：备注按原文位置去掉事件片段

事件维在自己的视图上认定事件后，记下该片段在原文中的起止。备注维在原文上按这个区间删除，再按备注视图去掉本维名词。不把事件视图整句交给备注。

## Risks / Trade-offs

- [两字词放开一个声母或一个声调后邻词变多] → 多个候选不替换；完全同音优先。
- [「是了」仍对不上「吃了」] → 声母和声调同时不同，不替换。
- [「陪方奶」对上「配方奶」] → 陪 pei2、配 pei4，声母和韵母相同，只有一个音节的声调不同。全表唯一则替换。
- [与未收版同音变更的共享稿行为不一致] → 实现时去掉「改写 draft.text 再给各维」的入口，只保留事件视图给事件维。
- [缺 pypinyin] → 视图等于原文，本地规则退回字面匹配。

## Migration Plan

先发 Python。回滚时恢复段入口的唯一同音整句替换，规则正则可暂时仍从名词模块拼出。无数据迁移，无 API 变更。
