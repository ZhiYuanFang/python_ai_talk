## Why

事件同音替换只认带调拼音完全一致，而且替换结果写进共享段文本，后面每一维都读这句改写稿。听写差一个声母时事件名和规则词都对不上；某一维先改写，又会动到其它维要认的名词。规则词散落在多处正则里，加一个说法也不能自动参与转换。

## What Changes

- 对照放宽为两种差法，一次只用一种：韵母相同，且整段恰好一个音节的声母不同；或声母和韵母相同，且整段恰好一个音节的声调不同。完全同音优先。零个或多个候选都不替换。少于两个音节的词不参与。
- 每一维只拿原文和这份只读拼音，用本维词表生成自己的视图。事件视图里的替换不得进入操作轨、播报、定位或备注的句子。
- 段入口把原文按字切成拼音一次。汉字留音节，数字和字母留空位，空位不参与比对，也不再因为夹着数字整句放弃替换。
- 规则名词的拼音在导入时写入全局缓存。事件正式名与 `extra_names` 的拼音在字典载入和手动刷新时写入缓存，请求路径不再转写词表。
- 事件名以外的规则名词集中到一个模块。各维正则从这些名词拼出，使新增名词同时进入本地规则和拼音缓存。
- 本维本地规则读本维视图。飞轮、小模型、对外复述和十分钟对话仍用语音识别原文。
- 备注去掉事件维已认定的片段时，按原文上的起止位置删除，不读取事件视图整句。
- 声母和声调同时不同的片段保持原文（例如「是了」对「吃了」）。同一个音节不能又改声母又改声调。
- 未收版变更 `intent-rules-homophone-gaps` 里「各维共用同一句事件替换稿」的行为，改成仅事件维使用事件视图。基线 `openspec/specs/v0.0.1.md` 尚无这条同音需求。

## Capabilities

### New Capabilities

- `per-dim-pinyin-view`: 原文拼音只切一次，各维用自己的词表缓存生成互不改写的视图，并在视图上跑本地规则

### Modified Capabilities

- 无。`openspec/specs/v0.0.1.md` 没有同音替换或规则名词词表的既有需求。

## Impact

- `app/feeding/services/event_homophone.py`：由共享整句替换改为可传入词表的视图转换，允许一个声母不同，或一个声调不同。
- 新增规则名词模块（事件名不写入该文件）；`dim_local_rules.py`、`history_speak_policy.py`、`segment_remark.py` 改为引用该模块。
- `segment_multidim.py`：各维本地规则改为读本维视图；`draft.text` 与飞轮、小模型保持原文。
- `event_cache.py`：字典载入与手动刷新时重建事件拼音缓存。
- 仍依赖 `pypinyin`。缺库时各维视图等于原文。
- 无对外 API 字段变更。
