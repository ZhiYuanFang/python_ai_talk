## Context

当前冷启动路径为：意图缓存未命中 → `remark_probe`（进行中摘要 + 可选备注 OOV 探针）→ `classify_intent`。备注分支用本地剥虚词抽出专名，调 Go filter 后压成「备注含 AD：营养品 ×3…」注入分类提示，但 Python **不**把命中写成 `event_id`。结果是：探针查到了映射，定事件仍靠模型读旁白；OOV 抽词失败时根本不查。

进行中计时摘要解决的是「停一下对准哪件」，与备注反查正交，应保留。

约束：经 HTTP 调兄弟仓；`feeding` 不得导入 `clinic`；中文业务注释；不写测试；禁止 `is_new_event` 建档。

## Goals / Non-Goals

**Goals:**

- 去掉分类前备注探针与 `remark_probe_hint` 注入。
- 分类先翻译 `op` / 事件名；字典匹配失败后再用该名称作 `remark` 调 Go filter 定事件。
- 唯一命中采用；多命中消歧；零命中（含首次记 AD）无法识别。
- 提示区分：表内活动简称/进行态可对真名；表外专名不得常识升格成类别。
- 字典规则匹配加强（剥「正在」等）以免「正在爬」误入备注反查。

**Non-Goals:**

- 不改 Go filter / batch 契约与备注可空 DDL。
- 不做「原话与表内名无共字则强制备注校验」层。
- 不恢复查询句正则、同音对照表、事件名向量匹配。
- 不把原始历史行注入分类 prompt。

## Decisions

### 1. 图：分类前只留进行中；备注反查放分类后

- **选择**：`remark_probe` 收窄为仅进行中（或改名 `in_progress_probe`）；缓存 miss → 进行中 → classify → **备注反查节点**（或分类末尾异步调用，图上须有明确步骤）→ 再按 `need_confirm` / op 路由。
- **原因**：定事件是查找，不应依赖模型读摘要；进行中仍需进 prompt。
- **备选否决**：继续先探针再分类；或完全去掉进行中。

### 2. 反查触发条件

- **选择**：对顶层与 `events[]` 各项：有名称且字典精确/包含/剥前缀包含均失败时，用该名称调 `get_filtered_history_events(device_no, remark=name, event_ids=None, 近窗, limit≤10)`。CRUD 均可触发，不限 read。
- **原因**：删/改「上次 AD」同样需要定叶子；首次记 AD 走零命中无法识别。
- **备选否决**：仅 read 反查；继续本地 `extract_oov_token` 门控。

### 3. 命中聚合与消歧

- **选择**：按 `event_id`（或字典可解析的 eventId）聚合。1 个叶子 → 填 `event_id`/`event_name`、`remark_keyword=专名`。≥2 → 复用父消歧同类 pending（选项为命中叶子），确认前不拉正式史、不落库。0 → `content`/`confirm` 说明无法识别；`event_id` 空；禁止建档。
- **原因**：用户明确要求多命中消歧、首次无法识别。
- **备选否决**：取众数静默；零命中用常识猜营养品。

### 4. 分类提示两条原则（不绑 op）

- **选择**：系统提示增加：
  1. 用户说的是表内已有活动的动作/进行态/简称时，必须填表内真名与 id（例：「正在爬」→ 爬练习）。
  2. 表里没有的专名/代号/商品名，不得凭常识改写成某分类事件；`event_name` 保持用户词，`event_id` 留空（交规则反查）。
- 删除 `remark_probe_hint` 相关段落；保留进行中摘要注入；仍禁止「上一次=read」类句式绑定。
- **原因**：避免「禁止一切改写」误伤爬练习；又拦住 AD→营养品。
- **备选否决**：禁止任何非字面匹配；恢复同音表。

### 5. 字典匹配加强

- **选择**：在 `_match_feeding_event`（或共享工具）中：精确 → 包含 → 剥进行态前缀（「正在」「在」等）后再包含。命中则不进备注反查。
- **原因**：模型若原样吐「正在爬」，规则仍能落到爬练习。
- **备选否决**：仅靠提示、不改匹配。

### 6. 状态字段

- **选择**：可移除或停用 `remark_probe_hint`；保留 `remark_keyword`、`in_progress_hint`。反查结果写入 `intent_result`，不另开原始行列表字段。
- **原因**：避免再把摘要注入 prompt。

## Risks / Trade-offs

- [模型仍把 AD 填成营养品] → 本版靠提示原则 2；不做共字强制校验。误填则不反查，可能错叶子。接受为已知风险，后续可加校验层。
- [「正在爬」剥前缀过宽] → 前缀白名单短；先精确再剥。
- [多事件一句部分在表部分不在] → 只对失败项反查；一项无法识别时整句需明确文案（实现时：该项 missing + 说明，不静默丢）。
- [分类后多一次 HTTP] → 仅字典失败才打；limit 小；比分类前常空跑更可预期。
- [光说 AD：分类判 create 还是 read] → 仍由 LLM 定 op；零命中则无法识别，不再「猜营养品再问记还是查」。

## Migration Plan

2. 回滚：回退镜像即恢复分类前备注摘要注入行为。
3. 无需迁库；Go 侧无强制变更。
