## Context

事件解析在 `resolve_event`：词典、别名、短说法向量、备注反查、事件小模型。唯一叶子会继续本轨并允许写事件说法飞轮。父事件在事后强制消歧。多候选和软确认停在 pending，未确认不执行。完全没对上则说无法识别。查记录仅在播报阶段、事件编号仍为空时做二十字猜测。

预测对接口时会把段事件按目录归到根，父级结果仍能对上。本变更不改这层匹配。

## Goals / Non-Goals

**Goals:**

- 把按附近历史选叶子封装进事件解析，查、预测、新增、修改、删除、结束计时共用。
- 父事件、未识别、多候选、软确认都先猜；猜中则不再问人（删除除外）。
- 猜中不写事件说法飞轮。删除猜中后落库前必须再确认。
- 没猜中保持现有问法、无法识别，以及查记录二十字猜测。

**Non-Goals:**

- 不改已唯一命中的叶子，也不因此关闭数量、时间、备注飞轮。
- 不改预测接口的叶子或根匹配顺序。
- 不删查记录二十字猜测；它只在猜事件失败且仍无编号时发生。
- 不把历史猜测记成覆盖缺口。

## Decisions

1. **挂在 `resolve_event` 阶梯之后，而不是各轨播报里。** 阶梯先得出「唯一叶子 / 父 / 多候选 / 软确认 / 未识别」。只有后四种进入猜测。猜中则改写成该叶子并打上「历史猜测」标记；猜不中则原样返回，后续消歧、软确认、无法识别不变。
2. **允许集合按触发原因收窄。** 父事件只给子孙叶子。未识别只给最近历史行里出现、且目录中存在的叶子。多候选和软确认只给本轮候选，禁止选到候选之外。模型返回空或集合外编号视为没猜中。
3. **附近历史是最近约二十条，忽略原话里的目标时刻。** 父事件已知时，拉取范围收在该父的子孙。避免按「要记到几点」去截窗口，也避免无界全量。
4. **删除单独确认。** 猜中且本段是删除时，不在当轮落库，走现有叶子确认；问句点出猜中的事件名。同意才删，不同意则取消。确认轮仍看得到历史猜测标记，因此不写事件说法飞轮。新增、修改、结束计时、查、预测猜中后直接继续。
5. **飞轮门闩只挡事件说法。** 标记传到查史播报、落库成功写短说法、以及确认后续写短说法三处。其它飞轮不读这个标记。
6. **提示词放在喂养 system 常量。** 模型只输出选中的事件编号。对外 SSE 上这次调用按现有约定流式并带中文思考。

## Risks / Trade-offs

- [猜错就新增或修改] → 只接受允许集合内的编号；失败则退回问人或无法识别，不硬写。
- [删除猜错] → 落库前必须再确认一次。
- [预测答话变成子事件名，时间仍可能来自父级] → 接受。归根匹配不改，避免为查或预测单独跳过猜测。
- [最近二十条里没有相关叶子] → 视为没猜中，行为与现在相同。

## Migration Plan

无数据迁移。上线后父事件和多候选会更多直接执行；删除仍会先问一句。回退即去掉解析末尾的猜测步骤。

## Open Questions

无。允许集合、删除确认、飞轮门闩和二十字兜底已按讨论定死。
