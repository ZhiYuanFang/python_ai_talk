## ADDED Requirements

### Requirement: 事件解析用附近历史猜测叶子

当事件解析结果不是「无需确认的唯一叶子」时，系统 MUST 在 `resolve_event` 内用附近历史猜测一个叶子事件。触发范围 MUST 包含父事件、完全未识别、多个候选、软确认。查记录、预测、新增、修改、删除与结束计时 MUST 共用该步骤，MUST NOT 为查记录或预测单独跳过。

附近历史 MUST 为最近有限条（约二十条），MUST NOT 按原话目标时刻无界拉取。父事件时允许集合 MUST 仅为该父的子孙叶子。完全未识别时允许集合 MUST 仅为这些历史行里出现且存在于目录的叶子。多候选与软确认时允许集合 MUST 仅为本轮候选。模型返回空或允许集合之外的编号时，系统 MUST 视为没猜中。

已经是无需确认的唯一叶子时，系统 MUST NOT 再猜测，事件说法飞轮 MUST 保持原行为。

#### Scenario: 父事件猜中子孙后不再消歧

- **WHEN** 解析命中父事件，且模型在该父子孙中选定一个叶子
- **THEN** 本段事件 MUST 为该叶子
- **AND** MUST NOT 再进入父事件消歧

#### Scenario: 多候选只许在候选内选择

- **WHEN** 别名、备注反查或软确认给出多个候选
- **AND** 模型选中其中一个候选叶子
- **THEN** 系统 MUST 按该叶子继续
- **AND** MUST NOT 改选候选列表之外的事件

#### Scenario: 没猜中则保持原路径

- **WHEN** 历史猜测没有得到允许集合内的叶子
- **THEN** 父事件、多候选与软确认 MUST 仍问人
- **AND** 完全未识别 MUST 仍返回无法识别
- **AND** 查记录在事件编号仍为空时 MUST 仍可走不超过二十字的答话猜测

### Requirement: 猜中后的执行与删除确认

历史猜测猜中叶子后，查记录、预测、新增、修改与结束计时 MUST 直接按该叶子继续，MUST NOT 再为该次猜测发起确认。删除 MUST NOT 在当轮落库，MUST 先发起叶子确认并在问句中点出猜中的事件名；用户同意后 MUST 才删除，用户拒绝后 MUST 取消且不删除。

#### Scenario: 新增猜中后直接记录

- **WHEN** 本段为新增且历史猜测选定一个叶子
- **THEN** 系统 MUST 按该叶子执行新增
- **AND** MUST NOT 先追问是哪个事件

#### Scenario: 删除猜中后先确认

- **WHEN** 本段为删除且历史猜测选定一个叶子
- **THEN** 系统 MUST 先询问是否删除该事件
- **AND** 用户同意前 MUST NOT 落库删除

### Requirement: 历史猜测不写事件说法飞轮

凡事件来自历史猜测，系统 MUST NOT 把本句写入事件说法飞轮。删除经用户确认后执行成功时，系统 MUST NOT 补写该事件说法。数量、时间与备注飞轮 MUST NOT 因本标记被关闭。

#### Scenario: 猜中执行后不入库短说法

- **WHEN** 叶子由历史猜测选定且本段执行成功
- **THEN** 系统 MUST NOT 调用事件说法飞轮写入

#### Scenario: 删除确认成功仍不入库短说法

- **WHEN** 用户同意删除一个由历史猜测选定的叶子且删除成功
- **THEN** 系统 MUST NOT 把确认前原话写入事件说法飞轮
