## Context

喂养必须精确到子（叶子）事件，不允许记录父事件。命中父时强制消歧。用户对系统提问的回应全部来自同一输入框的自由打字，**任何回应都有可能**——不是按钮式 `confirm|reject`。现有提问/确认流程与此产品现实不匹配，新功能研发中直接按新逻辑实现，不保留旧通道。

事件字典经 `http_client` → `event_cache`（24h TTL）进入意图与向量同步。需在保留 24h 刷新与飞轮的前提下，落地：全量+叶子、pending 消歧、自由文本解析（离题当新意图）。

仓库中已有部分实现（hierarchy / clarification / intent_pipeline / 路由与图改造），本 design 以最终产品契约为准，apply 时对齐补齐。

## Goals / Non-Goals

**Goals:**

- 只落叶子：任何路径最终 `event_id` 必须是无子节点事件
- 命中父强制消歧：名称/向量/LLM 命中父都不得直接 feeding 落库
- 同一 `/intent` + 可选 `conversation_id`；pending 下解析自由文本
- **任意打字可消化**：能唯一解析则落地；否则再问或拒绝；**无法归入选项/拒绝的一律清 pending 当新意图**（不白名单卡死）
- 飞轮仅在唯一叶子落地后写消歧前原话
- 保持 24h TTL 与增量同步；父标准向量移除；不删用户表达

**Non-Goals:**

- 不保留 `/intent/confirm` 与 `confirm|reject` 枚举主路径
- 不要求客户端改造成按钮选项（选项可返回供展示，但输入仍是自由文本）
- 不做跨进程 pending 持久化升级（进程内 pending 可接受）
- 不改变兄弟仓事件字典 API
- 消歧中途短回复（如「2」）不写入飞轮

## Decisions

### 1. 全量树 + 叶子视图

- **选择**：缓存保留全量；匹配/落库用叶子；父 = `event_id` 出现在任一非空 `parent_id` 中
- **理由**：消歧要父名与 children；落库只要叶子。http 出口直接丢父会导致无法检测父名
- **替代**：http 只返回叶子 —— 否决

### 2. 同一 `/intent` + 自由文本（取代旧提问流）

- **选择**：删除 confirm 枚举主路径；提问后用户继续在同一输入框打字并带回 `conversation_id`
- **理由**：产品明确「打字回应、任何回应都有可能」；旧流程假设非法
- **替代**：扩 `/intent/confirm` 收自由文本 —— 否决（多通道，易再错位）

### 3. 自由文本解析：有把握才落地，否则放行新意图

- **选择**：子名/`extra_names` → 序号 → 拒绝词 →（叶子软确认）肯定词 → 多匹配再问 → **其余 OFF_TOPIC 当新意图**
- **理由**：不把「未识别」当成错误态卡在消歧里；任意内容都能前进
- **替代**：每轮 LLM 解析 —— 成本高，非默认

### 4. 命中父一律消歧

- **选择**：精确父名、向量/LLM 得到父 `event_id`，全部改写为 pending 消歧
- **理由**：不允许记录父事件
- **替代**：仅名称路径 —— 否决

### 5. 飞轮时机

- **选择**：仅唯一叶子落地后，将**消歧前原话**挂到该叶子；序号/「是」等短回复不入库；父永不入飞轮
- **理由**：飞轮质量

## Risks / Trade-offs

- [自由文本误判离题或误选] → 唯一硬匹配优先；多命中再问；阈值可调
- [旧客户端仍调 confirm] → 不保留；契约与文档更新
- [存量父标准向量] → 同步删除标准条目；检索后仍拦截父命中
- [pending 进程内丢失] → 与旧 MemorySaver 同级，可接受

## Migration Plan

1. 对齐全量+叶子、父命中消歧、`/intent` pending 自由文本
2. 删除旧 confirm 主路径与死代码
3. 向量去掉父标准条目；飞轮只写叶子
4. 回归：叶子落地、父消歧、任意离题打字当新意图、24h、飞轮
