## Context

查史终答以本地模板为主。日汇总非次数问把紧凑历史（本地摘要加流水）原样返回。无事件编号时回复请先说明要查哪个事件。预测热路径已按叶子或归根对齐服务端锚点，但编号不一致或只有亲属侧有数据时仍会落入兜底。非计时新增在缺少结束时间时会把结束抄成开始，但开始与结束都有且不同时会保留两个时刻。规则缺口现用于时间与数量规则未覆盖；覆盖缺口用于答不出，二者不可混用。

## Goals / Non-Goals

**Goals:**

- 日汇总非次数问按语境出短规则答；未覆盖语境才模型，并记规则缺口。
- 无事件编号不再追问；有时间窗则全量，点查则全事件点查；模型不超过二十字；不写事件飞轮。
- 查史与预测：父无信息则试最近有信息的子事件并停止；子无信息则只再试父一次。
- 非计时新增与修改起止同一时刻，冲突时以结束时间为准。

**Non-Goals:**

- 取消消歧、软确认，或取消分段失败的无法识别覆盖缺口。
- 把「事件已对齐但没有记录」自动改成全量猜测。
- 计时事件开表（结束为空）或闭合补记（真实时长）改成同一时刻。
- 为亲属试探去重算预测算法或扩大算法七日窗。

## Decisions

### D1：日汇总语境策略

次数问维持现有「某天某事件 N 次」。非次数问先匹配预设语境，流水只作内部材料：

- 吃了哪些、吃了什么：只列食物或备注。
- 喝了多少：只报合计数量。
- 和昨天比、比昨天：只保留相邻日增减，不附流水。

未命中上述语境：紧凑历史加原话交给模型写短答，并 `rule_gap_store.record`，维度建议 `history_speak_context`。不得把本地摘要整段当作用户回答。

### D2：无事件编号

仅当查史项没有事件编号时进入。用上一步时间窗拉该窗全部历史；点查且忽略时间范围或窗为空时，按全事件点查取最近记录，禁止无界拉全库。模型回答必须不超过二十个字；失败则短硬句，仍不得追问事件名。不调用事件说法飞轮。规则缺口维度建议 `history_missing_event`。有事件编号但没有行，仍说没有相关记录。

### D3：亲属再试

查史「有信息」指拉到历史行；预测「有信息」指热路径锚点或预约约定，不把样本不足文案当成有信息。

- 目标是父且父侧无信息：在其子事件中选最近有信息的一个，命中即停。
- 目标是子且子侧无信息：只再试其父一次。
- 亲属试探不记覆盖缺口；两侧都无信息才走原兜底。

预测若服务端编号已等于目录根，现有叶子或根对齐应已命中；本条补的是「数据只挂在亲属编号上」的情况。

### D4：非计时同一时刻

字典类型不是计时：新增与修改的开始与结束写成同一 Unix 秒。两者都有且不同时采用结束时间，开始改成该结束时间。只有开始时，结束抄开始。计时开表仍允许结束为 0；计时闭合补记仍允许结束晚于开始。

## Risks / Trade-offs

- [二十字答非所问] → 只用于无事件编号兜底；日汇总已有规则的不套二十字。
- [最近子事件不是用户心里的那个] → 固定按最近记录选，不按字典顺序；用户可自行改口。
- [全量拉史过大] → 必须有窗或点查最近，禁止无界。
- [规则缺口变多] → 新维度与时间数量缺口分开，便于 Hub 筛选后补规则。

## Migration Plan

1. 落库时刻收敛（无用户听感依赖）。
2. 查史语境策略与无事件兜底。
3. 查史与预测亲属再试。
4. 回滚：关掉语境分叉与亲属再试即恢复整段摘要与追问事件。
